包内**少量**文件含**最小必要**的原文片段：槽位名与槽位默认值（如「青绿色」「宣纸象牙白」，

的判定证据，非全文转录；本文所用的**整条模板原文样本集未随包分发**。

按同一标准，两处成段原文样本在入包前做了处置，均已在件内显著标明：

- **12 号细读候选样本**：内含 30 余条完整模板原文，**整份未入包**，理由同上。

运行脚本前，请按 `00-取语料.py` 取到同一 commit，并按下节改一处路径常量。

## 三 · 怎么复现

脚本里的语料根路径写死在每个脚本开头一行：

```python
BASE = r'F:\数据集\水仙提示词库\shuixian-unified\data'
```

按自己的克隆位置改这一行即可，其余不用动。运行示例（Windows PowerShell）：

```powershell
python -I 01-核数与槽位全量.py | Out-File -Encoding utf8 01out.txt
python -I 36-槽位三种写法并集重算.py | Out-File -Encoding utf8 36out.txt
python -I 38-画论词在9118口径上_用19号算法.py | Out-File -Encoding utf8 38out.txt
python -I 60-注7零汉字三档复核.py | Out-File -Encoding utf8 60out.txt
```

`-I` 是**隔离模式**：不把脚本目录与当前目录加进模块搜索路径，避免目录里的同名文件
顶掉标准库模块。本文写作时一律以 `python -I` 调用。

作图脚本（`06-作图脚本/`）同理，只是它的 `BASE` 指向**论文目录**（它读稿本、不读语料），
且需 `matplotlib` 与 `Pillow`：

```powershell
python -I 91b-作图-模板解剖.py     # 出 图1 的 png / pdf / eps / tif
python -I 91c-作图-换轴并置.py     # 出 图2 的 png / pdf / eps / tif
```

两图的四件格式都由同一次运行、同一个 figure 对象出图：PDF／EPS 是**矢量**（字体按 TrueType
嵌入，非 Type 3），TIFF 由 24 位 PNG 无损转出（LZW，逐像素相同）。

**看结论的快路**：想核某一处数字，先查 `00-核数脚本与注释对应表.md`，再直接读 `02-中间结果/`
里对应的那份输出——多数问题不必跑脚本。

### 口径说明（复现前必读）

本文诸数有三处口径，脚本名与输出名里都带着记号，混用会算出不同的数：

1. **9,118 口径**（并集口径，本文正文与注释一律用此）＝三种槽位表面写法互不重叠后的并集：
   直引号式 2,932 条模板／8,152 个槽位，转义式 233 条／947 个，双反斜杠式 4 条／19 个。
   **9,090 口径**是更早一轮的两式合并口径，共 50 个含画论词的槽位，**已被取代**。
2. **汉字数 vs 字符数**：本文所标的「字」一律指汉字数（U+4E00–U+9FFF 的字符）。
3. **剔前 vs 剔后**：画论词计 1,931 词次为剔前，1,915 为剔除 16 处同形异义后。
   表 1 的 97.96% 与 2.04% 是对**剔后**算的。

## 四 · 复现审计（2026-10-10 本轮）

取包内脚本对同一 commit 的语料重跑，与 2026-10-09 的归档逐行对账：

| 脚本 | 复现结论 |
|---|---|
| `36-槽位三种写法并集重算` | ✅ 逐行一致 |
| `38-画论词在9118口径上_用19号算法` | ✅ 逐行一致（**注[5]／注[6] 的权威件**） |
| `43-三段切分在9118口径上` | ✅ 逐行一致 |
| `60-注7零汉字三档复核` | ✅ 逐行一致（2,515／2,305／210／161 四数同源） |
| `85d-基准线实测` | ✅ 逐行一致 |
| `89d-壬-42槽名全表复核` | ✅ 结数一致（42 实例／41 含汉字／34 种） |
| `27-两式合并后全面重算` | ⚠️ **逐词分解不稳**，见下 |

**关于 `27` 的不稳。** 同一条语料、同一份代码，两次运行给出**不同的逐词分解**：
「水墨」R=214→211、J=29→28，「墨色」R=41→44、J=2→3（总和 1,931 及三段合计均不变）。
原因是该脚本在用词表扫描文本时，对**互相重叠的词**（如「水墨」与「墨色」重叠于「水墨色」）
未安排确定性的先后次序，两次运行的落点不同。**这是该脚本的缺陷，不是语料变了。**

**对本包与论文的影响：无。** 因为：

- 论文正文与注释**不印任何逐词数**，只印合计（1,931／1,915／1,720／156／55／39／35／51／16），
  这些合计在两次运行中完全一致；
- 论文所用的 9,118 口径由 `38` 给出，而 `38` 已逐行复现。

`02-中间结果/27-…-2026-10-09.txt` 保留的是**写作当日**的输出；本轮重跑的结果另存为
`02-中间结果/27-…-重跑2026-10-10.txt`，两者并存，不做取舍、不掩盖差异。

### 本轮新增的两件（`187a`／`188a`，2026-10-12）

`189` 六处落稿所据的两处量测，随该轮入包（脚本与输出各一件，体例同 `85d` 与 `85`）：

| `188a-作者集中度` | 3,437 条 author 字段的集中度：HHI、top-k 份额、按人条数分桶 | ✅ 四处对账全中（98 条／2.85%、前 10 位 19.29%、前 50 位 42.01%、只写 1 条者 708 个＝63.50%） |
